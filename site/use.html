Use vet402 in your agent

Every way to ask vet402 before an agent pays, and how to let vet402 buy for it: a minimal example for each, and a link to the full spec.

Every check below reads the same public record and gives the same answer: pay, avoid or unknown, with one sentence of why and the numbers behind it. None needs a key or a payment. Proxy buy is the one way here that costs money.

What the verdict means

  • pay Most of vet402's paid calls to this seller were answered: the 95% interval of answered / counted is at or above 0.5 (the line for grade C), over 2 or more days.
  • avoid vet402 paid, and most paid calls were not answered: the interval's upper bound is below 0.5 (the line for grade D), over 2 or more days.
  • unknown Not enough to say pay or avoid: too little data, or vet402 never bought from this seller. With 1 to 3 counted calls the verdict is always unknown, and so it is for calls all made on one day.

Counted calls are paid calls: purchases whose payment settled, then answered or failed on the seller's side. A seller's 5xx with no settled payment is not a paid call, and with no settled payment the verdict is unknown. Failures that may be vet402's or the facilitator's, or whose cause cannot be told, never count. A payTo vet402 never paid turns pay into unknown. avoid is said only after vet402 has told the seller; until then the verdict is unknown.

On Robinhood Chain and Arbitrum, a purchase whose result is held until the seller is told is never used: the verdict comes from the published purchases, and the answer adds heldPurchases and heldNote. A seller with nothing but held purchases is unknown. The rule in code

As of the 2026-09-30 run, all 63 Arbitrum One sellers are unknown and all 14 Robinhood Chain sellers are unknown: vet402 bought from them in one run, on one day, which is too little to say pay or avoid.

HTTP: GET /v1/check

Any language, or a browser. Optional chain (solana, tempo, base, algorand, arbitrum, robinhood or a CAIP-2 id) and payTo (the recipient in the 402 you hold). CORS is open.

curl 'https://vet402-delivery.vercel.app/v1/check?url=https://api.xona-agent.com/token/pumpfun-trending'

The JSON starts with verdict and why; then tried, settled, counted, answered, days, the newest purchase and its tx, the newest signed records, and asOf. &format=html gives a page instead.

Python

Standard library only: ask before paying, and pay only when the verdict is not avoid.

import json, urllib.parse, urllib.request

def vet402_verdict(url):
    q = urllib.parse.urlencode({"url": url})
    with urllib.request.urlopen("https://vet402-delivery.vercel.app/v1/check?" + q, timeout=10) as r:
        return json.load(r)["verdict"]

if vet402_verdict(seller_url) != "avoid":
    pay(seller_url)

With the x402 Python client, register the example file's hook: x402HTTPClientSync(client).on_payment_required(vet402_on_payment_required) looks up the URL your code requested on every 402, before the client signs; on avoid the request raises PaymentError and the payment is never created. The file also sends the chain and payTo of each offer, and, like the fetch hook, goes on when the record cannot be read, saying so in one line.

Shell: curl

One line before the command that pays. pay stands for that command: it runs only when vet402 answered and the verdict is not avoid.

URL='https://api.xona-agent.com/token/pumpfun-trending'
# with jq
curl -fsSG -m 10 https://vet402-delivery.vercel.app/v1/check --data-urlencode "url=$URL" | jq -e '.verdict != "avoid"' >/dev/null && pay "$URL"
# without jq
curl -fsSG -m 10 https://vet402-delivery.vercel.app/v1/check --data-urlencode "url=$URL" | grep -o '"verdict": *"[a-z]*"' | head -1 | grep -Eq 'pay|unknown' && pay "$URL"

--data-urlencode sends the seller URL with its query string intact. If the check cannot be read (no network, or no answer in 10 seconds), pay does not run.

Spec: GET /v1/check

At the payment: the x402 fetch hook

Wrap the fetch your x402 client pays through. Every 402 is looked up before the client signs; with block: "avoid" the payment is never created for a seller whose answer is avoid.

npm install @vet402/check

import { wrapFetchWithPayment } from "@x402/fetch";
import { wrapFetchWithCheck } from "@vet402/check";

const fetchWithPay = wrapFetchWithPayment(wrapFetchWithCheck(fetch, { block: "avoid" }), client);

Add onCheck: (e) => ... to see every answer, or to write your own rule.

Any chain: the hook reads the network and payTo of every way to pay a 402 offers (x402 accepts, from the body or the PAYMENT-REQUIRED header, and an MPP WWW-Authenticate: Payment challenge), so it works under any x402 client that pays through fetch. Solana, Base, Tempo, Algorand, Arbitrum and Robinhood Chain are looked up per chain; any other network by URL and payTo. The package is named vet402-solana after the repository's first chain; the hook is not Solana-only.

Let vet402 buy it for you: GET /v1/buy

Solana only for now. Tempo is switched off on the live deployment, so where a line below names Tempo or USDC.e, it does not apply yet. The lines below are the README's own words.

An agent asks vet402 to buy a seller's answer for it. vet402 pays the seller from its own wallet only after the agent's payment has settled, and returns the seller's answer together with both transactions and a public record of the purchase.

Status on 2026-10-01: it runs at https://vet402-delivery.vercel.app/v1/buy, for Solana only (Tempo is switched off on that deployment, so no Tempo price is offered and a Tempo payment is refused).

curl -i 'https://vet402-delivery.vercel.app/v1/buy?url=<seller endpoint>'   # free: shows the price, charges nothing
  • Price: the seller's price plus 0.005 (USDC on Solana, USDC.e on Tempo).
  • Who vet402 buys from: only a seller host and payTo pair that vet402 already paid with a settled payment and that delivered at least once, read from data/
  • Refund: If the agent's payment settles and vet402 then does not pay the seller, vet402 refunds the full payment (seller price + fee) to the owner of the account whose balance paid (not a delegate that only signed), on the same chain in the same token.
  • No refund: If vet402 paid the seller (its payment to the seller settled) and the seller did not deliver, there is no refund. The purchase is recorded against the seller, with vet402's payment to it.
  • Large answers: an answer above 1,000,000 bytes is not forwarded, and since the seller was paid there is no refund
  • After a paid request: 200: the seller's answer byte for byte (content type kept), with x-vet402-customer-tx, x-vet402-seller-status, x-vet402-record and x-vet402-seller-settled
  • The record: GET /v1/buy/records/<id> returns the record: the seller endpoint without its query string, seller payTo and price, fee, total, both transactions, the seller's HTTP status, the sha256 and size of the answer, the outcome and the refund.
